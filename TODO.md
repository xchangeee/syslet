# Implementation gaps

Found while writing the docs; left undocumented on purpose until fixed, so the docs don't describe a hole as if it were a design.

## api spec issues

- **JSON `desiredState` defaults to `"stopped"`** — `parseDesiredState` in `internal/loader/v1.go` maps an omitted `desiredState` to `stopped`, while `#SysdefDefaults` sets `running`. Change the Go default to `running` too, then drop the "set it explicitly" note from [Manage containers](how-to/manage-containers.md#add-a-container) and state the default in [container.md](reference/spec-schema/container.md). Marker in [Manage containers](how-to/manage-containers.md).
- **JSON `removalAllowed` defaults to `false`** — the loader keeps Go's zero value, while `#SysdefDefaults` sets `true`. Change the Go default to `true` too. That reverses the premise of [Removing specs](explanation/removing-specs.md), which presents `false` as syslet's default protection; rework it and update the defaults tables in [Manage volumes](how-to/manage-volumes.md#know-your-defaults) and [Manage networks](how-to/manage-networks.md#know-your-defaults), the "JSON default" notes in [Manage containers](how-to/manage-containers.md#protect-a-container), and the `removalAllowed` rows in [container.md](reference/spec-schema/container.md), [volume.md](reference/spec-schema/volume.md) and [network.md](reference/spec-schema/network.md). Since `reclaimPolicy` now defaults to `"Delete"`, dropping an unlocked JSON volume would then delete its data, as it does in CUE.
- **`unit` is optional but should be required** — the v1 loader accepts container, volume, network and build specs without `unit` (`convertUnitOptions` returns `nil` for a missing map), and `#UnitSpec` declares `unit?`. Require it in both, allowing an empty object, and update the loader tests and integration fixtures that omit it. Then set `unit` back to required in [container.md](reference/spec-schema/container.md), [volume.md](reference/spec-schema/volume.md) and [network.md](reference/spec-schema/network.md), and add `"unit": {}` (CUE `unit: {}`) to the examples that omit it in [Adopt an existing volume](how-to/adopt-an-existing-volume.md) and [Connect containers on a network](how-to/connect-containers-on-a-network.md).
- **New units are assumed not running** — for a unit file syslet creates, it skips the runtime state query and plans a start. If a service with that name is already active, e.g. a hand-written quadlet whose file was moved away without stopping it, the start is a no-op and the old container keeps running. Marker in [Migrate hand-written quadlets](how-to/migrate-hand-written-quadlets.md).

## cli issues

- **No `--version` flag** — nothing in `cmd/syslet` reports a version, so the install step can't be verified and GoReleaser's injected build info is invisible. Add one, then add the check back to the tutorial.
- **`--diff` exits `0` on validation errors** — `cmd/syslet` only prints the plan in diff mode and never checks `plan.HasErrors()`, contradicting [cli.md](reference/cli.md#exit-behavior). Blocks the "Plan against the host" section of [Check changes in CI](how-to/check-changes-in-ci.md).
- **The plan prints secret values in plain text** — `Secret changes:` shows every new value, with no way to redact it, so a plan can't run in CI with shared logs. Also blocks the "Plan against the host" section of [Check changes in CI](how-to/check-changes-in-ci.md).

## behavior issues

- **`desiredState: "running"` with a user-set `Type=oneshot` gets `Restart=always`** — systemd rejects that combination. Use `desiredState: "oneshot"` for jobs, or have the renderer skip `Restart=` when the unit sets `Type=oneshot`.

- **`--stdin` persists before validating** — `api.LoadSpecsStream` writes `/etc/syslet/config.json` before the stream is even decoded, so a failed apply replaces the last good record with the broken input. Blocks saying whether `config.json` can serve as a fallback in [Roll back a deployment](how-to/roll-back-a-deployment.md).
- **A missing `sshKeyPath` file is skipped silently** — `cmd/syslet/main.go` only builds the decryptor when `fs.Stat(cfg.SSHKeyPath)` succeeds and says nothing otherwise. A typo in an explicitly configured `sshKeyPath` goes unnoticed until the first spec with a secret, and then fails with `no decryptor configured (SSH key path not set?)`, which names neither the path nor the cause. Any stat error, such as permission denied, is treated like a missing file. And without a decryptor, the keys already cached in `/var/lib/syslet/key.txt` aren't used either, so secrets fail even when the cache could decrypt them. Fail on an explicitly configured path that is missing, warn when the default is missing, only skip on not-exist errors, and name the path in the error. Marker in [Daemon config](reference/daemon-config.md).
- **`systemd-analyze verify` warnings block the apply** — `validate.Staging` records warnings (exit code 0) as plan errors, so they refuse the apply like failures do; the code comment suggests they were only meant to be surfaced. Decide which. Marker in [Troubleshoot a failed apply](how-to/troubleshoot-a-failed-apply.md).
- **Reclamation can strand a skipped container** — `validate.PostRender` checks that every volume/network/build a container references exists, but only across the *desired set*. Nothing checks references from units still installed on the host. So dropping a container spec and its volume spec in one change, where the container is `removalAllowed: false` (skipped, left running) and the volume is `removalAllowed: true` + `reclaimPolicy: "Delete"`, reclaims the podman volume out from under a container that is still mounting it. A host-side reference check over skipped/stale units before emitting `DeletePodmanVolume`/`Network`/`Image` ops would close it. See [removing-specs.md](explanation/removing-specs.md) for the behavior as currently documented.
- **No rebuild when a build's base image updates** — a build unit is rebuilt only when its Containerfile or context files change. A newer upstream image behind the same `FROM` tag is never picked up, and there's no command or option to trigger a rebuild. No how-to until this is designed.
- **A failed network delete doesn't fail the apply** — when a changed network is recreated, `podman network rm` runs through `applyRunner.exec`, which only logs errors. If something outside syslet still uses the network, the delete fails, the apply succeeds, and the network service's create-if-missing keeps the old network with its old settings. Marker in [Manage networks](how-to/manage-networks.md).
- **A stop passed on by `Requires=` leaves containers down** — syslet restarts a container as a separate stop and start, and picks what to start from each container's state at plan time. With `app` declaring `Requires=db.container` (or `BindsTo=`/`PartOf=`), a change to `db` stops `db.service`, systemd stops `app.service` with it, and only `db` is started again, so `app` stays down until the next apply. Start (or re-check) dependents after the start phase, or plan restarts along `[Unit]` dependencies. Until then the docs recommend `Wants=`. Marker in [Add dependencies between containers](how-to/add-dependencies-between-containers.md).
